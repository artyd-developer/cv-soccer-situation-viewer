# CV Soccer Situation Viewer

https://github.com/user-attachments/assets/4bed064c-84ab-4ab0-a69e-68cb9ad9e332

Приложение на основе компьютерного зрения для преобразования коротких футбольных видеофрагментов в интерактивные тактические ситуации.

Проект объединяет **детекцию объектов с помощью YOLO**, **поиск похожих игроков по цвету**, **PostgreSQL + pgvector**, **обработку в реальном времени через WebSocket** и интерактивную визуализацию тактической схемы.

---

## Возможности

- Загрузка футбольных видео через веб-интерфейс.
- Выбор **1-секундного** эпизода для анализа.
- Вырезка выбранного эпизода непосредственно в браузере с помощью **FFmpeg WebAssembly**.
- Отправка на backend только выбранного видеофрагмента.
- Обнаружение игроков и мяча с помощью **Ultralytics YOLO**.
- Расчёт цветовых векторов для обнаруженных игроков.
- Поиск визуально похожих игроков с помощью **pgvector**.
- Группировка игроков с настраиваемым порогом схожести.
- Ручное назначение групп игроков:
  - Teammate
  - Opponent
  - Unknown
- Визуализация игроков и мяча на тактическом поле.
- Отображение направлений движения с помощью стрелок.
- Получение прогресса анализа и обработанных кадров через **WebSocket**.
- Сохранение полученной тактической схемы.
- Открытие сохранённых ситуаций в отдельной странице 3d просмотра.

## Как это работает

### 1. Выбор видео

Пользователь выбирает футбольное видео через веб-интерфейс.

С помощью таймлайна можно выбрать момент, который необходимо проанализировать.

В текущей версии приложение работает с фиксированным **1-секундным видеофрагментом**.

---

### 2. Обработка видео на стороне клиента

Выбранный фрагмент извлекается непосредственно в браузере с помощью **FFmpeg WebAssembly**.

Полное исходное видео не требуется загружать на backend.

На сервер отправляется только выбранный 1-секундный фрагмент.

Это уменьшает объём передаваемых данных и позволяет выполнять первоначальную обработку видео непосредственно на стороне клиента.

---

### 3. YOLO-анализ

Backend получает выбранный фрагмент и обрабатывает его кадры с помощью **Ultralytics YOLO**.

В процессе анализа определяются:

- Игроки
- Мяч
- Координаты объектов
- Направление движения

Обработанная информация сохраняется backend и передаётся frontend во время анализа.

Frontend получает обновления процесса обработки через **WebSocket-соединение**.

---

### 4. Поиск похожих игроков и группировка

Для обнаруженных игроков backend рассчитывает цветовой вектор на основе их визуального представления.

Эти векторы сохраняются и сравниваются с помощью **pgvector**.

Игроки с похожими цветовыми векторами могут быть объединены в группы.

Порог схожести можно изменять непосредственно в интерфейсе.

Это позволяет пользователю управлять тем, насколько цветовые вектора игроков должны быть близки по косинусному сходству.

---

### 5. Назначение команд

На данный момент группы игроков не распределяются по командам автоматически.

Пользователь вручную классифицирует каждую группу:

- **Teammate**
- **Opponent**
- **Unknown**

Выбранная классификация применяется ко всем игрокам, входящим в соответствующую группу.

---

### 6. Тактическая схема

Обнаруженные объекты проецируются на тактическое футбольное поле.

Игроки отображаются разными цветами:

- **Teammate** - зелёный
- **Opponent** - красный
- **Unknown** - серый

Направления движения отображаются с помощью стрелок.

Мяч отображается отдельно.

После назначения группам команд полученную тактическую ситуацию можно сохранить и открыть в странице просмотра.

## Требования

Проект рассчитан на запуск с использованием **Docker** и **Docker Compose**.

Для основного сценария работы не требуется устанавливать Python или Node.js локально.

---

## Модель YOLO

Модель YOLO намеренно не включена в репозиторий.

Необходимо скачать требуемую модель и поместить её в:

```text
backend/yolo_model/yolo11n.pt
```

Модель не должна добавляться в Git.

Backend использует модель, указанную в:

```env
ULTRALYTICS_YOLO_MODEL=yolo11n.pt
```

---

## Настройки

Создайте `.env` в корне проекта на основе `.env.example`.

Пример:

```env
POSTGRES_DB=soccer
POSTGRES_USER=soccer
POSTGRES_PASSWORD=soccer

POSTGRES_PORT=5432
BACKEND_PORT=8000
FRONTEND_PORT=5173

ULTRALYTICS_YOLO_MODEL=yolo11n.pt
```

Создайте `frontend/.env`:

```env
VITE_API_URL=http://localhost:8000
```

---

## Запуск

После загрузки YOLO-модели и настройки переменных окружения запустите приложение:

```bash
docker compose up --build
```

Или запустите приложение в фоновом режиме:

```bash
docker compose up --build -d
```

Приложение будет доступно по адресам:

```text
Frontend:
http://localhost:5173

Backend:
http://localhost:8000
```

---

## База данных

Проект использует **PostgreSQL 16** с расширением **pgvector**.

Инициализация базы данных автоматически выполняется из:

```text
db/init/001_init.sql
```

Данные PostgreSQL хранятся в Docker named volume:

```text
postgres_data
```

Это позволяет сохранять данные базы при пересоздании контейнеров.

---

## API и обработка в реальном времени

Backend предоставляет REST API на базе **FastAPI**.

Во время обработки frontend получает информацию о процессе анализа, включая:

- Текущий кадр
- Номер кадра
- Метка времени
- Информацию о детекциях
- Прогресс обработки
- Статус завершения анализа

Это позволяет интерфейсу отображать процесс YOLO-анализа в реальном времени.

---

## Текущие ограничения

- Анализ в текущей версии ограничен **1-секундным видеофрагментом**.
- Назначение команд выполняется вручную после группировки игроков.
- Группировка игроков в основном основана на близости цветовых векторов.
- Полная коррекция перспективы камеры пока не реализована.
- Система ориентирована на анализ коротких тактических ситуаций.
